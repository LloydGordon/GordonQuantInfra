# WireGuard VPN on AWS

This Terragrunt/Terraform stack creates a WireGuard server in `us-east-1` on a
`t4g.nano`, the cheapest generally available EC2 On-Demand instance in that
region. It uses Amazon Linux 2023 ARM64, an encrypted 8 GiB gp3 volume, a stable
Elastic IP, and AWS Systems Manager Session Manager instead of exposing SSH.

## Project structure

The repository follows a root-include layout: shared provider and state settings
live in `root.hcl`, reusable Terraform lives under `modules`, and each leaf
`terragrunt.hcl` is an independently deployed unit with its own state key.

```text
WireGuardVPN/
├── root.hcl
├── modules/
│   └── wireguard/
│       ├── main.tf
│       ├── outputs.tf
│       ├── variables.tf
│       ├── versions.tf
│       └── user_data.sh.tftpl
└── environments/
    ├── dev/
    │   └── wireguard/
    │       └── terragrunt.hcl
    └── prod/
        └── wireguard/
            └── terragrunt.hcl
```

The root configuration generates the AWS provider and an encrypted S3 backend.
Terragrunt creates the account-specific state bucket when needed and uses native
S3 state locking. State paths are derived from `path_relative_to_include()`, so
development and production never share a state file.

## Cost

At current `us-east-1` rates, expect roughly **$7.36/month** before traffic:

- `t4g.nano`: about $3.07/month ($0.0042/hour)
- one public IPv4 address: about $3.65/month ($0.005/hour)
- 8 GiB gp3: about $0.64/month ($0.08/GiB-month)

CPU-credit overages and data transfer can add cost. The instance is configured
for `standard` CPU credits to prevent unlimited-mode CPU-credit charges.

AWS currently offers up to 750 hours/month of `t4g.small` compute under its
temporary T4g trial through December 31, 2026. If your account is eligible and
you prefer the promotional option, set `instance_type = "t4g.small"` in
`terragrunt.hcl`; switch back to `t4g.nano` before the promotion expires.

## Prerequisites

- AWS credentials with permission to create the resources in this stack
- Terraform and Terragrunt (managed by `tenv` is recommended)
- AWS CLI and the Session Manager plugin for administrative access
- WireGuard tools locally for generating client keys

Docker is the only local dependency for formatting, linting, and static
validation. The repository Makefile builds a pinned tooling image containing
Terraform, Terragrunt, and TFLint:

```bash
make format
make lint
make validate
make check
```

`make check` runs the same checks as the GitHub Actions workflow.

## Configure a peer

Generate the client key pair locally. Never commit the private key:

```bash
umask 077
wg genkey | tee client.key | wg pubkey > client.pub
cat client.pub
```

Copy the public key into the example `peers` block for the environment you want
to deploy. Assign a unique address such as `10.8.0.2/32` to each peer.

## Deploy

```bash
cd WireGuardVPN/environments/prod/wireguard
export AWS_ACCOUNT_ID="$(aws sts get-caller-identity --query Account --output text)"
aws sts get-caller-identity
terragrunt init
terragrunt plan -out=tfplan
terragrunt apply tfplan
```

Use `environments/dev/wireguard` instead for development. Deploying both creates
two complete VPN stacks and roughly doubles the monthly cost.

The first boot can take a few minutes while WireGuard is installed. Open an SSM
shell using the `ssm_start_session_command` output, then retrieve the public key:

```bash
terragrunt output -raw ssm_start_session_command
terragrunt output -raw server_public_key_command
```

Run the first command locally, then run the second inside the SSM session.

## Client configuration

Create `wg0.conf` on the client using its private key and the Terraform outputs:

```ini
[Interface]
PrivateKey = CLIENT_PRIVATE_KEY
Address = 10.8.0.2/32
DNS = 1.1.1.1

[Peer]
PublicKey = SERVER_PUBLIC_KEY
Endpoint = PUBLIC_IP:51820
AllowedIPs = 0.0.0.0/0
PersistentKeepalive = 25
```

Then connect with `wg-quick up wg0` or import the configuration into a WireGuard
client application.

Changing `peers` changes EC2 user data and intentionally replaces the instance,
which also rotates the server key. Update the server public key on every client
after such a change.

## State and teardown

State is stored in the account-specific S3 bucket generated by `root.hcl`. The
state key includes the environment and unit path. Terraform state and plan files
remain ignored by Git.

To remove all billable resources:

```bash
terragrunt destroy
```
